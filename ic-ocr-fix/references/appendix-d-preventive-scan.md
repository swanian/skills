## 附录D: 预防性扫描机制

### D1: 写入前预检流程

在将截图识别的内容写入文件之前，执行以下预检可以大幅减少后续修正工作。

#### 触发条件（满足任一即执行）

```
□ 文件扩展名为 .sv / .v / .vh / .svh （SystemVerilog/Verilog）
□ 文件扩展名为 .tcl （TCL脚本）
□ 文件扩展名为 .ralf （RALF寄存器定义）
□ 文件扩展名为 .f （Filelist文件）
□ 文件内容包含 run 命令（仿真时间控制）
□ 文件内容包含 ral:: 命令（寄存器访问）
□ 文件内容包含 `uvm_ 宏（UVM框架）
□ 文件内容包含 > 或 >>- 或 >- 符号（疑似伪影）
```

#### 预检步骤

##### 步骤1: 快速视觉扫描（3秒）

```
浏览文件内容，寻找明显的异常：
  □ 是否有行首的 > >>- >- 符号？
  □ 是否有类似 "run Xus" 但X不是数字？
  □ 是否有 "ral:X" 但X不是 :: ？
  □ 是否有 `uvm_xxx 但反引号看起来奇怪？
  □ 是否有大段代码的缩进明显不对齐？
```

如果发现任何异常，标记该区域并进入深度检查。

##### 步骤2: 自动化模式匹配（应用附录B的正则）

对高风险文件应用关键正则：

```bash
# 高优先级检查（必须通过）:
1. /\brun\s+[0-9]*[lIOoSsZz][0-9]*\s*(us|ns|ps|fs|ms)\b/  # 时间单位混淆
2. /^(?:>>-|>-|>)(?=[A-Za-z_`])/m                          # 伪影污染行首
3. /\bral:[wrds]\b/                                        # RAL命令错误

# 中优先级检查（警告，需上下文确认，命中≠错误）:
4. /(?:0[xX]|'[hH])[0-9a-fA-F]*[OoIiIlSsZz][0-9a-fA-F]*/  # 十六进制混淆
5. /`uvm_\w+utils/i            # UVM宏检查
6. /\btype\s+id\s*::/i         # Factory空格错误
```

##### 步骤3: 上下文语义验证

对模式匹配命中的结果进行人工确认：

```
对于每个命中：
  1. 查看命中行的上下文（前后各2-3行）
  2. 判断这是否真的是OCR错误：
     - 是 → 记录并计划修正
     - 否（误报）→ 忽略，添加到白名单
  3. 如果确认是错误，立即修正后再写入文件
```

##### 步骤4: 写入后验证

写入文件后，执行最终检查：

```
□ 文件已成功创建/更新？
□ 文件大小合理（不为0字节）？
□ 快速打开文件目视检查无明显乱码？
□ 如果是SV文件，begin/end大致匹配？
□ 如果是TCL文件，大括号 {} 大致匹配？
```

### D2: 高风险文件特征识别

根据历史经验，以下特征的文件更容易产生OCR错误：

#### 高风险指标

| 指标 | 风险等级 | 原因 | 应对策略 |
|------|---------|------|----------|
| **缩进层级≥4层** | 🔴 极高 | 深层嵌套代码易产生折叠标记 | 重点检查行首伪影 |
| **包含大量宏调用** | 🔴 高 | 反引号和长参数易丢失 | 逐一验证UVM宏完整性 |
| **包含时间控制命令** | 🔴 高 | 数字/字母混淆高发区 | 严格验证时间数值 |
| **包含十六进制数** | 🟠 中 | 0/O, 1/I/l 混淆 | 检查所有hex常量 |
| **包含长标识符** | 🟠 中 | 长名字易被打断 | 验证关键字连续性 |
| **文件行数<30行** | 🟡 低-中 | 短文件信息量少，难以纠错 | 对照截图仔细核对 |
| **纯配置文件(.f/.prj)** | 🟡 低-中 | 特殊格式易被破坏 | 遵循格式规范检查 |

#### 风险评分算法

```
总分 = Σ(各指标权重 × 是否存在)

权重分配:
  缩进≥4层:        +3分
  宏调用>5处:      +2分
  时间控制命令:    +3分
  十六进制数>3处:  +2分
  长标识符>5个:    +1分
  文件<30行:       +1分
  配置文件:        +1分

风险等级:
  0-2分: 🟢 低风险 - 标准流程即可
  3-5分: 🟡 中风险 - 建议执行预检步骤1-2
  6-8分: 🟠 高风险 - 必须执行全部预检步骤
  ≥9分: 🔴 极高风险 - 建议人工逐行审核后再写入
```
