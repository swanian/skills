# Screenshot to Files - 截图文件结构重建器

## 功能概述

将用户提供的**文件结构截图**（如 `tree -L N` 输出）和**文件内容截图**转换为实际的文件系统结构，并维护项目进度文档。

## 触发条件

- 用户发送 `tree -L N` 命令的终端截图
- 用户发送文件编辑器的代码/文本内容截图
- 用户要求"按照这个结构建立文件夹"或"创建文件并写入内容"

---

## 工作流程

### 阶段1: 接收文件结构

1. **识别目录结构**: 解析 tree 输出，区分文件（无 `/` 或有扩展名）和文件夹（有 `/`）
2. **创建目录和空文件**:
   ```powershell
   New-Item -ItemType Directory -Path "目标路径\文件夹名" -Force   # 文件夹
   New-Item -ItemType File -Path "目标路径\文件名" -Force           # 文件
   ```
3. **确认正确性**: 列出已创建的结构，请用户确认（特别是文件vs文件夹混淆时）

### 阶段2: 接收文件内容

1. **识别截图内容**: 从 GVIM/MiniBufExplorer 等编辑器截图中提取文本，保留原始格式
2. **写入文件**: 使用 `Write` 工具写入完整内容
3. **自动执行基础修正**: 写入后自动移除编辑器伪影符号（`>`, `>>-`, `>-`, 孤立行号等），无需询问
4. **询问是否深度修正**: 基础修正完成后，询问用户：
   ```
   ✅ 已写入 [文件名] ([X]行) — 已自动清理编辑器伪影符号

   📋 是否需要执行以下操作？
   1️⃣ 调用 ic-ocr-fix 进行深度OCR纠错（关键字/TCL/RAL/断行等）
   2️⃣ 更新PROGRESS.md进度文档
   3️⃣ 两者都执行
   4️⃣ 都不需要，继续下一个文件
   ```

#### 多页截图拼接规则（GVIM 整页截图必读）

一个文件常由多张连续截图覆盖，拼接错位是最高频的结构性错误。

| 版式特征 | 说明 |
|---|---|
| 左侧灰底数字 | **绝对行号**，不是代码内容 |
| 相邻页重叠 | 通常 1~3 行重叠，用于对齐 |
| 右侧状态栏 | `行,列 位置` / `百分比`，需剥离 |

```
拼接算法:
1. 每页先剥离左侧灰底行号列与右侧状态栏，得到 (起始绝对行号, 文本行列表)
2. 相邻页按绝对行号对齐，重叠部分取内容一致的行
3. 行号连续才拼接；出现跳号 = 中间缺页，必须停下来报告，禁止跳过
4. 禁止按视觉顺序硬拼 — 翻页键可能先触发导致首帧丢失或截到未重绘旧帧
```

**行号跳变是缺页信号**。发现跳号立即停止并报告，让用户补拍；不得用上下文推导填充。

### 批量转换流程（截图目录快模式）

适用于目录中已积压 N 张编辑器截图、需批量复原代码文件的场景（code_ocr 项目实测：43 张 → 6 个文件）。

```
1. 分族: 每族先读 1 张看 GVIM 标题栏/标签栏，按"激活标签"把截图归组到源文件；
   捕获时间戳只作分族辅助线索。标签栏里从未激活的文件 = 截图没拍到，
   报告为未覆盖，禁止建空文件编造内容。
2. md5 去重: 自动翻页采集会产生完全相同的重复帧（实测一族 13 张里 7 张重复）；
   先 md5sum，subagent 只读唯一帧。另一族可能零重复，去重是廉价保险。
3. 并行派发: 按源文件（不是按截图族、不是串行）一个 subagent，同一消息内全并行。
   prompt 必须写明: 每图只读一遍；禁止像素级测量（数字符横线长度、量列对齐空格），
   空白缩进目测最佳努力；写完自查引号奇偶/括号配平并上报。
4. 转写规则下发: 左侧灰底数字=绝对行号；剥离标签栏/MiniBufExplorer/状态栏/光标行/
   EOF 波浪号/diff 红竖条；按绝对行号拼接、重叠行去重；行号跳变=缺页，插 [OCR-GAP]
   标记禁止编造；VCS filelist 的 +incdir+/+define+/-F 是真实语法，不是 diff 伪影；
   转写完成后对**文本**跑一遍 ic-ocr-fix 规则扫描（关键字/正则/结构校验），不回读截图，
   仅个别疑难字符裁原图回查。
5. 抽查验证: 全部 agent 返回后，主 agent 每族读 1 张原图与落盘文件逐行比对，通过才收尾。
6. 删除截图: 全部族完成且抽查通过后才删。删前 git ls-files 确认截图是否被跟踪:
   被跟踪=可从历史恢复；未跟踪=明确警告用户不可逆后再删。
```

**速度瓶颈（实测）**: 像素级测量是最大瓶颈——同批启动的 agent 中做测量者比不做者晚约
15 分钟落盘；禁止测量后 21 张图 2 个 agent 同一分钟落盘。读图本身（每张约 1–2k token）不可压缩。

**代价**: 注释横幅横线数、列对齐空格数变为目测最佳努力，可能有 ±1 误差；代码 token 不受影响，抽查与截图逐行一致。

### 阶段3: 维护进度文档

在目标根目录维护 `PROGRESS.md`，**仅在用户确认后更新**（详见下方机制）

#### 落位约定

截图目录名与目标文件名同名。转换完成后，把截图目录改名为 `<文件名>_`
（加下划线后缀），代码文件写到同级。这样 `gb_uvm/gb_assert.sv_/`（截图）
与 `gb_uvm/gb_assert.sv`（产物）可共存，`git restore` 不会冲突。

## 关键规则

### 文件 vs 文件夹判断

| 特征 | 文件 | 文件夹 |
|------|------|--------|
| tree 后缀 | 无 `/` 或有扩展名 | 有 `/` |
| 示例 | `change.tcl`, `run_cmd` | `apb/`, `src/` |
| 处理方式 | `New-Item -ItemType File` | `New-Item -ItemType Directory` |

### 错误纠正

用户指出类型错误时 → 删除错误项 → 重新创建 → 直接修正，无需道歉

### 路径约定

- 默认根目录: 用户当前工作目录下的 `code_origin/`
- 实际使用根据用户指定调整，支持相对/绝对路径

### 文件名纠正机制

**触发条件**: 
1. 用户明确指出命名错误
2. 从截图内容中发现实际文件名与创建时不一致
3. 截图标题栏显示正确文件名（如 `[9:apb_rm_cfg.sv]*`）

**纠正流程**:
```
步骤1: 识别错误 → 发现 {旧文件名} 应为 {新文件名}
步骤2: 删除错误 → Remove-Item {旧文件路径}
步骤3: 创建正确 → New-Item -ItemType File {新文件路径}
步骤4: 更新PROGRESS → 修改状态表中的文件名
步骤5: 写入内容 → 将截图内容写入正确命名的文件
```

**识别方法**: 查看截图编辑器标题栏、检查代码中的类名/模块名匹配、注意 `ifdef` 宏定义

**示例**: 标题栏显示 `[9:apb_rm_cfg.sv]*` → 发现之前创建的 `apb_rm.cfg.sv` 错误 → 删除并创建正确的 `apb_rm_cfg.sv` → 写入内容并更新PROGRESS.md

### 截图内容识别错误修正机制（两层策略）

**问题背景**: 从截图中识别代码时，可能会遇到编辑器UI伪影或OCR误差，导致代码中混入非语法符号。

#### 第1层: 基础自动修正（内置，无需询问）

写入文件后**自动执行**，清理常见的编辑器伪影符号：

| 错误模式 | 正确格式 | 自动修正操作 |
|----------|----------|-------------|
| `>function` / `>class` / `>task` | `function` / `class` / `task` | 移除行首 `>` |
| `>>-super.new(` / `>>-endfunction` | `  super.new(` / `endfunction` | 移除 `>>-`，保持缩进 |
| `>-rand uvm_reg` / `>-int addr` | `  rand uvm_reg` / `  int addr` | 移除 `>-`，添加2空格缩进 |
| `>>-\`uvm_object_utils` | `` `uvm_object_utils `` | 移除 `>>-` |
| 代码中混入孤立行号 | 删除行号数字 | 仅当明显是行号时（如独立数字行） |

**自动修正范围**: 仅限行首伪影符号 `>`, `>>-`, `>-` 和孤立行号，不影响代码语义

#### 第2层: 深度OCR纠错（需要用户确认，调用 ic-ocr-fix）

对于需要语义理解的复杂错误，询问用户后调用 **ic-ocr-fix Skill**：

| 错误类型 | 典型场景 | 需要 ic-ocr-fix |
|----------|----------|----------------|
| 数字↔字母混淆 | `run 1us` 写为 `run lus` | ✅ |
| SV关键字错误 | `endclass` → `endc1ass`, `rand` → `rand` 误识 | ✅ |
| TCL/RAL命令错误 | `ral::wr` → `ral:wr`, `run 1us` → `run 1us` 漏识别 | ✅ |
| 字符串断行错误 | UVM消息字符串被换行符截断 | ✅ |
| 数据类型错误 | `logic [31:0]` → `Iogic [31:0]`（I→l混淆） | ✅ |
| 行首伪影符号 | `>function`, `>>-super.new` | ❌ 第1层自动处理 |

**询问时机**: 基础自动修正执行完毕后，由阶段2步骤4的菜单询问用户

#### 识别方法

**1. 语法检查**:
- 函数定义: `function/task/class` 前不能有 `>` 或 `>>-`
- 宏调用: `` `uvm_object_utils `` 前不能有 `>>-`
- 变量声明: `rand/int/logic` 前不能有 `>-`

**2. 上下文一致性检查**:
- 缩进级别应一致（不能突然出现额外符号）
- 类似结构的代码应有相同的格式

**3. 用户反馈**:
- 用户指出某行代码有问题时，立即检查是否包含非语法符号
- 用户选中特定行并询问时，重点审查该行的异常字符

### 注意事项

1. 不要主动创建文档文件，除非是 PROGRESS.md
2. 不要添加注释到代码文件中，保持原始内容
3. 每步操作后确认状态，避免累积错误
4. 支持中断恢复：用户可随时切换到其他子目录

## 📊 PROGRESS.md 更新机制（按需执行）

**核心原则: 写入文件后询问用户，仅在用户确认后才更新 PROGRESS.md！**

### 触发与更新方式

| 操作类型 | 是否需要询问 | 更新内容 |
|----------|-------------|----------|
| **✅ 写入文件** | 询问用户 → 确认后更新 | 标记为 ✅ 已完成(X行) → 统计表+1 → 重算百分比 |
| **📁 创建目录** | 询问用户 → 确认后更新 | 添加到结构树 → 标记子项为⏳ → 统计表+N → 添加待办项 |
| **🔧 修正错误** | 询问用户 → 确认后更新 | 更新条目类型 → 同步统计数据 |

### PROGRESS.md 必须包含的要素

```markdown
# 项目文件结构重建进度
> 更新时间: YYYY-MM-DD HH:MM | 目标路径: `<路径>`

## 目录结构状态表
| 文件/文件夹 | 状态(✅🔄⏳🔲) | 说明 |

## 下一步清单
1. [ ] 当前任务待办
2. [ ] 后续任务
```

### 状态图标规范

| 图标 | 含义 | 使用场景 |
|------|------|----------|
| ✅ | 已完成 | 文件有内容 / 目录所有子项完成 |
| 🔄 | 进行中 | 部分子项已完成 |
| ⏳ | 等待 | 空文件或空文件夹 |
| 🔲 | 未开始 | 尚未创建的顶层目录 |

### 操作后检查点（仅在用户确认更新时执行）

```
□ Write 操作后 && 用户确认更新 → 更新文件状态
□ New-Item 操作后 && 用户确认更新 → 添加新条目
□ 修正操作后 && 用户确认更新 → 更新统计数据
```

## 📌 主动提醒机制（重要）

**触发场景**: 每次完成操作后 / 用户说"继续/好的/不知道" / 对话停顿时

### 核心提醒模板

#### 模板A: 操作完成后（通用）

```
✅ 已[创建/写入] [对象] ([X]行)

📋 接下来请发送：
1️⃣ 文件内容: [列出等待内容的空文件]
2️⃣ 子目录结构: [列出需要展开的文件夹]
3️⃣ 或切换到其他目录: [列出未开始的顶层目录]
```

#### 模板B: 用户迷茫时（完整选项菜单）

```
📍 当前位置: [路径] | 📊 完成度: XX%

【继续当前目录】
• 文件内容: [具体列表]
• 子目录结构: [具体列表]

【切换目录】
• dir1/ (未开始) • dir2/ (未开始) • ...

【查看状态】
• 输入 "进度" 查看 PROGRESS.md
```

### 提醒规则

| 规则 | 说明 |
|------|------|
| **必须主动** | 操作完就提醒，不等用户问 |
| **提供选项** | 给出 2-4 个明确可选项 |
| **显示上下文** | 告知当前位置和进度 |
| **优先级排序** | 最需要的放第一位 |
| **简洁明了** | ≤15 行，用 emoji 增强可读性 |

### 特殊情况速查

| 场景 | 处理方式 |
|------|----------|
| 用户长时间无响应 | 发送简化版: "等待指示... 可发送截图/输入'继续'/切换目录" |
| 收到无关内容 | 提示: "当前期待[具体内容]，请重新发送或切换任务" |
| 多次未更新PROGRESS | 回溯补全所有遗漏的更新项 |
| 目录全部完成 | 引导选择下一个顶层目录或生成最终报告 |

## 最佳实践速查

**核心流程**: tree截图 → 批量创建 → 内容截图 → Write写入 → 自动清理伪影符号 → 询问是否深度纠错+更新PROGRESS → 主动提醒
**批量快模式**: 按激活标签分族 → md5去重 → 按源文件并行subagent（每图单读、禁像素测量）→ 主agent抽查比对 → 确认后删截图
**关键要点**: 基础修正自动执行无需询问；深度纠错和PROGRESS更新需先询问用户

## 附录B: 仿真工具链关键知识

### VCS 编译常用选项

| 选项 | 说明 |
|------|------|
| `-full64` | 64位模式编译 |
| `-sverilog` | 支持SystemVerilog |
| `-ntb_opts uvm-1.2` | 启用UVM 1.2库 |
| `-timescale=1ns/100ps` | 设置时间精度 |
| `-debug_acc+all` | 启用全部调试功能 |
| `-kdb` | 启用Verdi知识数据库 |
| `-cm line+cond+fsm` | 启用代码覆盖率 |
| `+define+UVM_OBJECT_DO_NOT_NEED_CONSTRUCTOR` | UVM宏定义 |

### 运行模式（来自 .prj 文件）

| 模式 | 说明 | 继承关系 |
|------|------|----------|
| `atom` | 原子模式（基础配置） | 无 |
| `base` | 基础模式 | extend:atom |
| `regress` | 回归测试模式 | extend:base |

### 覆盖率类型

| 类型 | 选项 | 说明 |
|------|------|------|
| Line Coverage | `-cm_line` | 行覆盖率 |
| Condition Coverage | `-cm_cond` | 条件覆盖率 |
| FSM Coverage | `-cm_fsm` | 状态机覆盖率 |
| Branch Coverage | `-cm_branch` | 分支覆盖率 |

### RALF 转 UVM 命令

```bash
# 使用 Synopsys ralgen 工具
ralgen -full64 -uvm -t top_sys top_sys.ralf
```

| 参数 | 说明 |
|------|------|
| `-full64` | 64位模式 |
| `-uvm` | 生成UVM兼容代码 |
| `-t top_sys` | 指定顶层系统名称 |
